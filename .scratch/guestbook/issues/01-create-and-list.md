# 01: 방명록 글 작성과 목록 조회

**What to build:** 방문자가 가입 없이 이름, 메시지, 비밀번호를 입력해 방명록 글을 남기면, 그 글이 한 페이지짜리 목록 맨 위에 바로 나타난다. 목록에는 모든 방명록 글이 작성 시각 최신순으로 보이고, 각 글에는 이름, 메시지(줄바꿈 유지), 작성 시각(한국 시간)이 표시된다. 입력이 잘못되면 어느 항목이 문제인지 안내하고, 입력한 내용은 지우지 않는다. 이 티켓에는 뒤 티켓들이 기대는 기반 작업이 함께 들어간다: 방명록 글 스키마와 첫 마이그레이션, 저장소 인터페이스(Neon 구현과 메모리 구현), 방명록 모듈, Vitest 설정. 자세한 결정은 [spec](../spec.md) 참고.

**Blocked by:** None (can start immediately)

**Status:** done

- [x] 구현 전에 이 Next.js 버전의 문서(`node_modules/next/dist/docs/`)에서 Server Actions, 폼 상태, 캐시 무효화 방법을 확인했다
- [x] 방명록 글 테이블(id, 이름, 메시지, 비밀번호 해시, 작성 시각 `timestamptz`, 수정 시각 null 허용)의 Drizzle 스키마와 생성된 SQL 마이그레이션 파일이 커밋되어 있고, `db:migrate` 스크립트로 로컬에서 적용할 수 있다
- [x] 방명록 모듈이 저장소 인터페이스에만 의존하며, 작성과 목록 조회 동작을 제공한다. 결과는 성공 또는 항목별 입력 오류를 구분하는 합 타입이다
- [x] 앞뒤 공백 제거 후 이름 1–20자, 메시지 1–500자(줄바꿈 유지), 비밀번호 4–32자(공백 제거 없음)를 서버에서 검증한다
- [x] 비밀번호는 글마다 다른 솔트를 붙인 `crypto.scrypt` 해시로 저장하며, 목록 조회 결과와 화면 어디에도 비밀번호나 해시가 나오지 않는다
- [x] 목록은 작성 시각 내림차순이고, 같은 시각이면 id 내림차순이다
- [x] 작성 시각은 Asia/Seoul 기준 `YYYY-MM-DD HH:mm`으로 표시된다
- [x] 방명록 글이 없으면 비어 있다는 안내가 보인다
- [x] 작성에 성공하면 폼이 비워지고 목록에 새 방명록 글이 바로 반영된다. 실패하면 항목별 안내가 보이고 입력값은 남아 있다
- [x] 메시지 안의 HTML·스크립트 문자열은 글자 그대로 표시된다
- [x] 메모리 저장소를 쓰는 Vitest 테스트가 방명록 모듈의 작성·조회 동작을 검증한다: 작성한 글이 목록에 나타나고 해시가 없음, 정렬 규칙, 항목별 입력 오류, 같은 이름 허용
- [x] `npm test`, `npm run lint`, `npm run build`가 통과한다
